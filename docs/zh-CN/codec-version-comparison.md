# LHDC V2～V5 与 LLAC 对比

[English](../codec-version-comparison.md) | 简体中文 | [文档索引](README.md)

核对日期：2026-10-22。本说明依据当前发布版源码与公开接口，描述本库实际实现，不将所有使用这些名称的产品宣传能力视为本库能力。默认 BT 分支为 `LHDC_BT_USE_AOSP_REFERENCE=0`。

## 总体关系

V2、V3、V4 属于同一套“PCM 量化、预测、残差压缩”体系。V3 增加自适应 LPC 并缩短块长；V4 在同一核心上增加扩展信令。V5 改用独立的 MDCT 频谱编码体系。

LLAC 也是变换编码，但拥有自己的整形、边信息、熵编码及解码器，既不是普通 V4 的一个质量档位，也不是可与 V5 互换的码流。

源码目录 `lhdc/encoder/src/v4/` 同时包含 **V2、V3、V4 和 LLAC**，不能将目录名直接当成实际码流版本。

## 版本编号与接口映射

| 码流 | 编码器创建方式 | 解码初始化版本 | 实现归属 |
|---|---|---:|---|
| LHDC V2 | `lhdcBT_get_handle(1)` | `200` | V4 组件中的预测核心 |
| LHDC V3 | `lhdcBT_get_handle(2)` | `300` | V4 组件中的预测核心 |
| LHDC V4 | `lhdcBT_get_handle(3)` | `400` | V4 组件中的预测核心 |
| LLAC | `lhdcBT_get_handle(4)` | `500` | V4 组件中的独立 LLAC 核心 |
| LHDC V5 | `lhdcv5BT_get_handle(1, &handle)` | `550` | 独立 V5 组件 |

编码创建参数与解码协议版本属于不同编号体系。旧 BT 接口的 `4` 选择 LLAC，而非普通 LHDC V4；解码版本 `500` 也是 LLAC，而非 V5。V5 使用单独接口，其创建参数 `1` 是 V5 接口/核心修订编号，不代表 LHDC V1。

## 编码与解码算法

| 项目 | V2 | V3 | V4 | LLAC | V5 |
|---|---|---|---|---|---|
| 主要表示 | 量化 PCM 与预测残差 | 同一体系 | 同一体系 | MDCT 频谱 | MDCT 频谱 |
| 预测或整形 | 固定阶差分及左右声道差分选择 | 增加自适应量化 LPC | 延续 V3 | SNS、TNS | SNS/ADSQ 尺度因子组织 |
| 主要载荷编码 | Rice 或 LHDC 专用 LZ，另有原始/常量模式 | 同类残差编码，加 LPC 参数 | 同类编码，加扩展字段 | 谱值对上下文算术编码、逃逸位、符号位、残差位 | 预测位平面、FAC 算术编码、符号及余数 |
| 编码 FFT 的作用 | 分析频谱，控制量化及质量 | 同 V2 | 同 V2 | MDCT/DCT 变换组成部分 | MDCT/DCT 变换组成部分 |
| 主要重建 | 整数预测及残差重建 | 增加 LPC 重建 | 同类核心，加扩展解析 | 频谱、噪声填充、逆 TNS/SNS、IMDCT | 频谱重建与缩放、噪声填充、定点 FFT 及时域合成 |

V2～V4 中存在 FFT，不代表传输的就是 MDCT 系数。它们通过频谱分析决定 PCM 量化强度，随后预测并压缩样本或残差；LLAC 和 V5 则实际量化、传输变换系数。

V2～V4 的 LZ 流交替使用字面量块与长度/距离回溯块，不是 LHA 文件，也不是标准 LH4～LH7 Huffman 流。

## PCM 格式与帧长度

| 项目 | V2 | V3 | V4 | LLAC | V5 |
|---|---|---|---|---|---|
| BT 编码采样率 | 44.1/48/96 kHz | 同 V2 | 同 V2 | 包装接受相同采样率，仍受核心及模式检查限制 | 44.1/48/96/192 kHz |
| BT 编码输入位深 | 16/24 位 | 同 V2 | 同 V2 | BT 为 16/24 位 | 16/24/32 位容器 |
| 编码块 | 每声道 512 样本 | 每声道 256 样本 | 每声道 256 样本 | BT 初始化为标称 5 ms | BT 初始化为 5 ms |
| 48 kHz 下输入块时长 | 约 10.67 ms | 约 5.33 ms | 约 5.33 ms | 5 ms，240 样本 | 5 ms，240 样本 |
| 受检公开解码采样率限制 | V4 接口接受 44.1/48/96 kHz | 同 V2 | 同 V2 | 受检绑定拒绝 96 kHz，使用 44.1/48 kHz | 独立 V5 初始化，包含高采样率配置 |

需要区分接口层次与实际范围：

- LLAC 内部编码接口包含 32 位容器与 2.5/5/10 ms 配置路径，但 BT 包装限定 16/24 位并选择 5 ms，不能直接将内部能力归入 BT 接口。
- LLAC 编码可初始化 96 kHz 高分辨率模式，但本库受检公开 LLAC 解码器拒绝 96 kHz，不能宣称该组合已经支持端到端解码。
- V5 编码的 32 位输入是容器，内部提取有效 24 位，不代表完整 32 位无损保真。
- 帧样本数及容量应从当前实例查询，尤其 44.1 kHz 不应简单用标称时长乘输入采样率代替查询。
- 输入块时长不是蓝牙端到端延迟；还需考虑组包、调度、宿主队列、无线传输及接收端缓冲。

## 码率与流控

| 项目 | V2～V4 普通 LHDC | LLAC | V5 |
|---|---|---|---|
| 常规最高固定 BT 档位 | 900 kbps | 包装提供至 900 kbps 的档位，仍受核心码率、帧长、模式检查限制 | 1000 kbps |
| AUTO 索引 | `8` | `8` | `9` |
| 默认 AUTO 起始目标 | 400 kbps | 400 kbps | 400 kbps |
| 调节方式 | 队列统计、质量限制、帧及 MTU 预算 | 独立 LLAC 队列及预算路径 | 独立队列控制、按采样率选择的码率表及上下限 |

V4 家族共用表包含 `64、128、192、256、320、400、500、900、1000` kbps，但索引八表示 AUTO，其 `1000` 表项不等于常规固定 1 Mbps 档位。普通 LHDC 还会将低码率限制到至少 128 kbps；开启最低限制后为 320 kbps，不能仅看表项判断实际输出设置。

LLAC 初始化还保留状态相关行为：在交替的初始化阶段，900/600 kbps 目标可更新扩展模式状态，64 kbps 可按输入位深更新自动码率标志。因此，这些值在该路径中不只是码率选择。重复配置需要明确实例生命周期，不能假设初始化没有历史状态。

V5 默认表的固定档位为索引 0～8，九为 AUTO。44.1 kHz 下，中间的 256/500 kbps 档位变成 240/480 kbps。AUTO 索引中的 `2000` 表项不证明存在固定 2 Mbps 模式；实例上下限和自定义码率表也会影响选择结果。组包字节取整还可能使实际码率与请求值不同。


## 相邻版本的主要变化

### V2 → V3

V3 将输入块减半，并把自适应 LPC 加入固定差分预测的候选集合，按残差成本选择编码方法，同时改变帧/包预算并包含版本相关的左右差分处理。这不是仅改帧头编号，但仍属于同一预测编码家族。

### V3 → V4

主要预测、量化和残差编码大量共用。明确新增的是扩展帧头、AR/JAS 信令与 META 负载；帧头写出在版本码不大于 399 时跳过该扩展逻辑。默认包装只为普通 V4 和 LLAC 创建可选 AR 状态，不为 V2/V3 创建。

AR 是独立 PCM 效果器，不属于残差编码本身。宿主可以显式用独立 PCM 接口先处理音频，再交给 V2/V3 编码，但这不等于它们具备相同的内置 BT AR 接入。

### V4 → V5

V5 改用变换域载荷，拥有独立帧头、频带表、尺度因子、熵编码状态和解码合成链，并增加 192 kHz 输入及常规 1 Mbps 档位。不能通过修改 V4 的版本字段完成升级。

### LLAC 与 V4、V5

LLAC 是托管在 V4 组件中的独立低延迟变换路径。相对普通 V4，它采用 MDCT 系数、SNS/TNS 和谱值对算术上下文；相对 V5，其边信息、码本、增益、残差组织及帧格式不同。共用 FFT/DCT 基础设施不会使码流互通。

## 数值路径、内存与性能

- V2～V4 同时包含浮点频谱/LPC 分析与整数量化、残差重建。
- LLAC 使用浮点 MDCT/SNS/TNS 与整数量化、算术编码；其解码器接入公共浮点 DCT-IV。
- V5 编码仍以浮点为主，`LHDC_V5_ENCODER_FIXED_FFT=ON` 只替换 FFT 部分，窗及旋转仍为浮点。V5 解码在合成链中使用公共定点 FFT。
- V3 块较短不代表 CPU 开销一定低于 V2，因为增加了 LPC 分析；V4 扩展或 V5 名称也不能直接决定速度和音质。
- 实例容量受 ABI、采样率、帧长、AR 及 FFT 后端影响，应使用公开工作区查询。[模块体积统计]将 V2～V4/LLAC 归入 V4 组件，不是逐协议版本的独立体积测试。

## 兼容性与接入

1. 区分码流协商版本与 API 参数，使用匹配的编码入口和解码初始化编号。
2. V2～V4 共用解码实现，但预测及帧头语义不同；LLAC、V5 使用独立码流，不能交换版本号来解码。
3. 区分 PCM 有效位深与字节容器；编码紧凑 PCM 与解码 32 位槽之间可能需要显式转换，见[功能说明]。
4. AR 可独立处理 PCM，按需显式接入，不能将扩展标志视为各版本处理完全等同的证明。
5. 数学、FFT、内存和环形缓冲共用不意味着可变编码状态共用；实例应使用独立句柄/工作区，同一实例串行调用。
